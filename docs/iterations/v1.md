# v1: Real service

**Goal:** turn the laptop script into a service running in Azure, with no secrets anywhere. The whole environment is created from code with one command and removed with another.

## What's included

```
AI-Demo/
├── app/
│   ├── config.py           # settings come from env vars, never from code
│   └── main.py             # FastAPI: POST /chat, GET /healthz
├── infra/
│   ├── main.bicep          # resource group + outputs for azd
│   ├── resources.bicep     # identity, Azure OpenAI, registry, Container Apps
│   └── main.parameters.json
├── azure.yaml              # tells azd what to build and where to deploy it
├── Dockerfile
└── requirements.txt
```

`hello.py` and `.env.example` are gone.

## What changed

**From script to API.** The same chat call now sits behind `POST /chat` in FastAPI, running on Azure Container Apps. It scales to zero when nobody is using it.

**From API key to managed identity.** The app has its own Entra ID identity and gets short-lived tokens for Azure OpenAI. The only code change is the `api_key` argument:

```python
token_provider = get_bearer_token_provider(
    DefaultAzureCredential(), "https://cognitiveservices.azure.com/.default"
)
client = OpenAI(base_url=f"{settings.openai_endpoint}/openai/v1/", api_key=token_provider)
```

`DefaultAzureCredential` uses the managed identity in Azure and your `az login` / `azd auth login` account on your laptop, so the same code runs in both places. On the Azure OpenAI resource, `disableLocalAuth: true` turns key-based access off completely.

**Least privilege, declared in code.** The identity gets exactly two roles: *Cognitive Services OpenAI User* on the OpenAI resource (it can call models but not manage deployments or read keys) and *AcrPull* on the registry. You, as the person running `azd`, get the same OpenAI role so you can run the app locally.

**Config split from code.** The endpoint and deployment name come from env vars. Bicep sets them on the container; locally they come from `azd env get-values`.

**Infrastructure as code.** `azd up` creates the resource group, builds the image in Azure Container Registry (no local Docker needed), and deploys it. `azd down --purge` removes everything, including the soft-deleted OpenAI resource.

## Demo script

1. **`azd up`.** One command, about five minutes, nothing clicked in the portal.
2. **`curl -X POST $SERVICE_API_URI/chat -H 'Content-Type: application/json' -d '{"question": "How do I connect a second monitor?"}'`** The same answer as v0, now from a URL.
3. **Watch it break:** get a key with `az cognitiveservices account keys list` and call the model with it. The keys still exist, but the call returns **403: key-based authentication is disabled**. A leaked key is useless.
4. **Watch it hold:** search the repo and the container's settings for a secret. There isn't one.
5. **`azd down --purge`.** Everything is gone, and `azd up` brings it back the same way.
